## 2. Sample data (the demo)

Persona: Maya, 21, club soccer, ACL reconstruction 8 weeks ago, PT twice a week, goal "back on the pitch". Seed covers Oct 5 to Oct 25 (21 days):

- Extension improves from 8° short of straight to 0° on day 15 (milestone fires). Flexion climbs from 95° to 128°.
- 3 game days (days 4, 11, 18), 6 PT days, 4 gym days, the rest walking or rest.
- 4 flare-ups: 3 the morning after game days, 1 after a gym day. Each has a pain log the evening before with a chip, and a "Did it settle?" answer the next morning.
- Morning check-ins every day; swelling "some" after game days.
- Load per day computed by the core model from the logged activities so the Load tile and the weekly bars are consistent with the logs.

Generated by `packages/core/src/sim/seed.ts`, deterministic, with a test that the insights rules produce the game-day observation.

## 4. Getting it onto a phone by Monday

This is the one thing that cannot be forced. Two paths:

- **Path A, TestFlight.** Only possible if an Apple Developer Program membership already exists on someone's account. Then: `eas build --platform ios --profile preview` Saturday, `eas submit` Sunday, testers install Monday. EAS build queue on a free plan can take an hour or more; start the first build Saturday morning with the shell app to shake out signing.
- **Path B, direct install from Xcode.** No Developer Program needed. `npx expo prebuild`, open the iOS project in Xcode, sign with a free personal team (any Apple ID), plug in the demo iPhone, run. The app works for 7 days before it needs re-signing, which covers Monday. Also works for a second teammate's phone if they plug it in.

Recommendation: do Path B regardless, since it is guaranteed. Do Path A in parallel only if the account exists. If enrollment has to start now, it will not be approved by Monday; TestFlight comes the week after.

Open:
- **EAS login and the first TestFlight build** need Matthew's Expo and Apple logins; commands are in `apps/mobile/README.md`.
- **Local native build from this folder.** The repo sits in the iCloud-synced Desktop, and iCloud tags freshly built framework folders with Finder attributes that break code signing (`resource fork, Finder information, or similar detritus not allowed`). Redirecting only the framework build (`EXPO_CUSTOM_BUILD_ROOT`) gets past signing but then the Pods cannot find the moved framework. The working approach is a second checkout outside iCloud: a git worktree of `main` at `~/kinn-native`, used only for `expo run:ios` and device installs (`cd ~/kinn-native && git merge main` to pick up changes). EAS cloud builds are not affected.
- Palette and type: still placeholders, waiting on Figma.
- Nine Expo packages are a patch version behind (`npx expo install --check`); harmless for the demo, run it before the TestFlight build.
